# Feature Spec: Foundation — Cleanup, Dependencies, Theme & Env

**Phase:** 1 (Foundation)
**Branch:** `feature/cleanup-spec`

The repo is currently create-next-app boilerplate with Sanity bolted on. This feature clears the template out, installs the animation and SEO dependencies the spec calls for, defines the design tokens, and documents the environment variables — so that every later feature starts from the real palette, the real fonts, and a working `.env`.

Nothing visual is built here. The page ends as a near-empty placeholder on the correct background in the correct fonts.

---

## Goals

### 1. Strip create-next-app boilerplate

- `app/page.tsx` — remove the template landing page (Next/Vercel logos, Templates and Learning links, Deploy Now / Documentation buttons). Replace with a minimal placeholder that proves the theme is live.
- `app/layout.tsx` — remove the Geist / Geist_Mono imports and their variables; replace the `Create Next App` / `Generated by create next app` metadata with real title and description; keep `lang="en"`.
- `public/` — delete the unused template assets (`next.svg`, `vercel.svg`, `file.svg`, `globe.svg`, `window.svg` — whichever are present).
- `app/globals.css` — remove the `--background: #ffffff` / `--foreground: #171717` defaults, the `prefers-color-scheme: dark` block, and the `font-family: Arial, Helvetica, sans-serif` body rule.

### 2. Dependencies

Install:

- `gsap` — the only animation library on this project
- `@gsap/react` — provides `useGSAP`, the SSR-safe hook for running GSAP inside React

Already present, no action needed: `next-sanity`, `sanity`, `@sanity/vision`, `@sanity/image-url`, `styled-components` (Sanity peer dependency), `tailwindcss` v4, `@tailwindcss/postcss`.

Deliberately **not** installed:

- `@vercel/analytics` — optional in the spec; deferred to the deploy phase, where it can actually do something
- `schema-dts` — deferred to the SEO/metadata work, since nothing emits JSON-LD yet
- No component library, no state manager, no form library, no second animation library

### 3. Fonts

Via `next/font/google` in `app/layout.tsx`:

| Font           | Role                       | Weights | CSS variable     |
| -------------- | -------------------------- | ------- | ---------------- |
| Inter Tight    | Display / headings         | 600–700 | `--font-display` |
| Inter          | Body                       | 400–500 | `--font-sans`    |
| JetBrains Mono | Metadata, labels, eyebrows | 400–500 | `--font-mono`    |

- `display: 'swap'` on all three
- `subsets: ['latin', 'latin-ext']` — `latin-ext` is required for the diacritics in "Radosław Siek"
- Variables applied to `<html>`, consumed by the `@theme` block

### 4. Design tokens in `app/globals.css`

Tailwind v4 `@theme` block. **No `tailwind.config.ts` / `.js` file** — creating one is a spec violation.

| Token                    | Value     | Usage                             |
| ------------------------ | --------- | --------------------------------- |
| `--color-base`           | `#0A0B0E` | Page background, never pure black |
| `--color-surface`        | `#121419` | Cards, panels                     |
| `--color-surface-raised` | `#191C23` | Hover states, nested panels       |
| `--color-border`         | `#252932` | Hairline borders, dividers        |
| `--color-fg`             | `#E8E6E3` | Headings and body, never `#FFF`   |
| `--color-fg-muted`       | `#8A8F9A` | Labels, metadata, captions        |
| `--color-accent`         | `#00E5C7` | The single accent                 |

Also in `@theme`:

- Font tokens mapping `--font-display` / `--font-sans` / `--font-mono` to the three `next/font` variables
- Radius: `4px` for small elements, `8px` for cards

Base layer:

- `body` — `base` background, `fg` text, Inter, `1.6` line-height, antialiased
- Visible focus ring in `accent` for keyboard navigation
- **Dark only** — no `dark:` variants, no `prefers-color-scheme`, no toggle anywhere

Not in this feature: the faint grid/dot texture and grain overlay. They belong with the layout work.

### 5. Environment files

Create `.env.example` — **committed**, no real values, each key annotated with where to obtain it:

| Key                              | Where it comes from                                                        |
| -------------------------------- | -------------------------------------------------------------------------- |
| `NEXT_PUBLIC_SANITY_PROJECT_ID`  | sanity.io/manage → project → Project ID (also `sanity.cli.ts`)             |
| `NEXT_PUBLIC_SANITY_DATASET`     | sanity.io/manage → project → Datasets (usually `production`)               |
| `NEXT_PUBLIC_SANITY_API_VERSION` | A date string pinning the API; defaults to `2026-08-27` in `sanity/env.ts` |
| `SANITY_API_READ_TOKEN`          | sanity.io/manage → API → Tokens → Add token, **Viewer** permission         |
| `NEXT_PUBLIC_SITE_URL`           | The deployed origin, e.g. `http://localhost:3000` locally                  |

Then:

- Fill `.env.local` with the values that exist — it already has `NEXT_PUBLIC_SANITY_PROJECT_ID` and `NEXT_PUBLIC_SANITY_DATASET`
- Confirm `.env.local` is git-ignored and `.env.example` is not
- `SANITY_API_READ_TOKEN` is a **secret** — no `NEXT_PUBLIC_` prefix, never referenced from a client component

## Notes

**GSAP licensing** — verified against current GSAP docs: the standard `gsap` npm package is free for commercial use, and the formerly Club-only plugins (ScrollTrigger, SplitText, etc.) are now included. No paid tier and no private registry config is needed for the four effects in the Animation Budget.

**GSAP usage rules for later features** (recorded here so they're settled before the first animation):

- Register once at module level: `gsap.registerPlugin(useGSAP, ScrollTrigger)`
- Always animate inside `useGSAP(() => {...}, { scope: containerRef })` so selectors stay scoped and animations revert on unmount
- Wrap animations created in event handlers with `contextSafe()`
- GSAP is browser-only — it lives in `'use client'` components and must never run during the server render

**Out of scope:** Sanity schemas (`project` / `technology` / `testimonial`), Studio structure, seed content, background texture, and every component in the spec's component table.

**Adjacent fixes, folded in only on request:**

- `sanity/lib/client.ts` sets `useCdn: true`; the planned ISR (`revalidate: 3600`) wants `false`
- `app/layout.tsx` does not render `<SanityLive />`, so `sanityFetch` will not live-update
